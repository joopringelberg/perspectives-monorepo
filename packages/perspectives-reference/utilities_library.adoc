=== ReplaceR

`<valueExpression> >> ReplaceR( <pattern>, <replacement> ) returns String`

`ReplaceR( <pattern>, <replacement>, <value> ) returns String`

Replace parts of a string with another string.

[cols="1,1,4"]
|===
|Parameter/Result|Type | Explanation

|pattern|Regular expression|A regular expression in string form, like the parameter of the https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_expressions#creating_a_regular_expression[Javascript RegExp object].
|replacement|String|A string to replace the matches with.
|value|String|The string value in which the replacement takes place.
|result (functional)|String|The string with the replacement.
|===

[code]
----
callExternal util:ReplaceR( "\\$.*$", "NewName", Repositories$NameSpace ) returns String
----
NOTE: to use a character class like \n in a regular expression, _escape_ the backslash (\) character with another backslash, like this: \\n.

=== FormatDateTime

`<stringExpression> >> FormatDateTime( <date>, <locale> ) returns String`

`FormatDateTime( <date>, <locale>, <options> ) returns Number`

Format a date.

[cols="1,1,4"]
|===
|Parameter/Result|Type | Explanation

|date|DateTime|A DateTime Value(see below).
|locale|String|A locale according to the [specification], e.g. "en-EN" or "nl-NL".
|options|String|This should be the serialisation of a JSON object: all identifiers and string are required to be in double quotes and these quotes must be escaped by a backslash to prevent breaking the surrounding string.
|result (functional)|String|A string that shows the date (and optionally time) in the required format.
|===

DateTime (PDate) values can be entered literally in Perspectives Language, or can be entered through the user interface, or can be read from the system clock (see the Sensor library, device "clock", sensor "now"). For the form of the literal representation see https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/parse#Date_Time_String_Format[DateTime String Format] on MDN. Summary: the type must conform to YYYY-MM-DDTHH:mm:ss.sssZ, but time may be left out.

The options object may contain any key-value pairs as specified in https://tc39.es/ecma402/#sec-createdatetimeformat[this ECMA specification].

For a discussion of the `locale` and the `options` object, see https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat[DateTimeFormat] on MDN.

[code]
----
callExternal util:FormatDateTime( SomeDate, "nl-NL", "{\"dateStyle\": \"full\", \"timeStyle\": \"short\"}" ) returns Number
----

=== CreateInvitation
`CreateInvitation( <message>, <serialisedTransaction>, <confirmationCode> ) returns <String>`

Given a serialised transaction and the string representation of a ConfirmationCode, creates a serialised Invitation.

[cols="1,1,4"]
|===
|Parameter/Result|Type | Explanation

|message|String|A readable message for the destination user.
|serialisedTransaction|String|A serialised context that will be uploaded to the destination user's installation. It will then be parsed into an Invitation context.
|confirmationCode|String|A confirmation code that will be used to confirm the transaction.
|result|String|A serialised Invitation context that can be sent to the destination user.
|===

The following is an excerpt from the Perspectives System model, which shows how to use the CreateInvitation function. It is used to create an invitation for a user to connect with another user. The serialised transaction is created by serialising the context that contains the role types that are relevant for the invitation.


[source,perspectivesarc]
----
  case Invitation
    external
      property SerialisedInvitation (File)
      property CompleteMessage = ...
      property ConfirmationCode (Number)
      property InviterLastName = context >> Inviter >> LastName
        readableName
      ...
      state CreateInvitation = exists ConfirmationCode
        on entry
          do for Inviter
            letA
              transaction <- callExternal ser:SerialiseFor( ... ) returns String
              invitation <- callExternal util:CreateInvitation( CompleteMessage, transaction, ConfirmationCode ) returns String
            in
              create file ("invitation_of_" + InviterLastName + ".json") as "text/json" in SerialisedInvitation for origin
                invitation
----

=== GetSharedFileServerKey
`GetSharedFileServerKey( <sharedFileServerKey> ) returns <String>`

Given the users' own SharedFileServerKey, fetches a new key from the Perspectives Shared File Service.
This is used by the manager of the BrokerService to provide new users with a SharedFileServerKey that they can use to store files in the Shared File Service. This manager is by construction the first peer to get into contact with a new installation.

[cols="1,1,4"]
|===
|Parameter/Result|Type | Explanation

|sharedFileServerKey|String|The user's own SharedFileServerKey that will be used to fetch a new key.
|result|String|A new SharedFileServerKey that can be used to store files in the Shared File Service.
|===

The following is an excerpt from the Perspectives System model, which shows how this function is used.
[source,perspectivesarc]
----
    user PerspectivesUsers (relational)
      ...
      property SharedFileServerKey (String)
      state NoKey = (not HasKey) and (exists sys:SocialMe >> SharedFileServerKey)
        on entry
          do for Initializer
            SharedFileServerKey = callExternal util:GetSharedFileServerKey( sys:SocialMe >> SharedFileServerKey ) returns String
            HasKey = true
      property HasKey (Boolean)
----

=== SetCurrentLanguage
`SetCurrentLanguage( <key>, <value> )`

Sets the current language in the PerspectivesState and in IndexedDB. This is used to set the language for the user interface and other language-dependent features.

NOTE: The `key` is always "currentLanguage" and the `value` is a string that represents the language code, such as "en-US" or "nl-NL". The value is stored in the PerspectivesState and in IndexedDB. Notice, too, that the first parameter should be factored out.

[cols="1,1,4"]
|===
|Parameter/Result|Type | Explanation

|key|String|Should always be "currentLanguage".
|value|String|The language code, such as "en-US" or "nl-N
|===

[source,perspectivesarc]
----
  callEffect util:SetCurrentLanguage( "currentLanguage", CurrentLanguage )
----

=== IsLowerVersion
`IsLowerVersion( <version1>, <version2> ) returns <Boolean>`

Compares two Semantic version strings and returns true if the first version is lower than the second version.
[cols="1,1,4"]
|===
|Parameter/Result|Type | Explanation

|version1|String|The first version string to compare.
|version2|String|The second version string to compare.
|result|Boolean|True if the first version is lower than the second version, false otherwise.
|===

The following is an excerpt from the Perspectives System model. It is a simplified version of the condition on a state that is used to run an upgrade script when the Perspectives system is upgraded to a new version. The condition checks if the last handled upgrade is lower than the version of the upgrade script, and if the current version of the Perspectives system is lower than the version of the upgrade script.

[source,perspectivesarc]
----
        state Upgrade3_0_9 = callExternal util:IsLowerVersion( LastHandledUpgrade, "3.0.9" ) returns Boolean and 
          (callExternal util:IsLowerVersion( "3.0.9", callExternal util:SystemParameter( "PDRVersion" ) returns String) returns Boolean) 
----
