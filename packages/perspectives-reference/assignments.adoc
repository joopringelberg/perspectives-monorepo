[desc="Assignments change property values and create or delete roles or contexts."]
[[concept-assignment]]
== Assignments

_Assignments_ are statements that modify the state of a Perspectives model at runtime. They are used in <<state_declarations-automatic-effects,automatic effects>> (`do` blocks), in <<keyword-action,actions>>, and in `letA` blocks.

Every assignment modifies contexts, roles, or property values. Assignments may be preceded by a `letA` block that binds intermediate expression results to local variables.

[[keyword-letA]]
=== letA — local variable bindings

[[assignments-let]]
[source]
----
letA
  <name> <- <expression>
  ...
in
  <assignment>*
----

The `letA` construct binds query expressions to lowercase variable names. Variables are evaluated once and may be reused in subsequent bindings or in the assignment statements that follow.

Example:
[source, arc]
----
letA
  app <- create context MyApp
  start <- create role StartContexts in sys:MySystem
in
  bind_ app >> extern to start
  Name = "My App" for start
----

NOTE: Use `letA` (not `letE`) when you want assignment statements in the body. `letE` is for expression-only pipelines.

[[assignments-property]]
=== Property assignments

==== Set a property value

[source]
----
<PropertyName> = <expression> [for <roleExpression>]
----

Replaces the current value(s) of `<PropertyName>` with the result of `<expression>`. The optional `for <roleExpression>` clause specifies the role instance on which the property is set; when omitted, the default role instance determined by the enclosing context is used.

Example:
[source, arc]
----
Status = "active"
Title = "My Document" for extern
----

==== Add a property value

[source]
----
<PropertyName> =+ <expression> [for <roleExpression>]
----

Adds the result of `<expression>` to a relational (multi-valued) property. When the property is functional (single-valued), `=+` behaves identically to `=`.

Example:
[source, arc]
----
Tags =+ "urgent" for origin
----

[[keyword-remove-property]]
==== Remove a property value

[source]
----
<PropertyName> =- <expression> [for <roleExpression>]
----

Removes the specific value produced by `<expression>` from a relational property.

Example:
[source, arc]
----
Tags =- "draft" for origin
----

==== Delete a property

[source]
----
delete property <PropertyName> [from <roleExpression>]
----

Removes _all_ values of `<PropertyName>` from the role instance. The optional `from` clause identifies the role instance; when omitted, the default role instance is used.

Example:
[source, arc]
----
delete property DraftNote
delete property CacheValue from origin
----

[[assignments-role]]
[[keyword-create]]
=== Role assignments

==== Create a role instance

[source]
----
create role <RoleName> [named <expression>] [in <contextExpression>]
----

Creates a new instance of `<RoleName>` in the current context (or in `<contextExpression>` when given). The optional `named <expression>` clause provides a local name for the new role instance, useful when the role requires an indexed name.

Example:
[source, arc]
----
create role Participant
create role Task named ("task-" + nextId) in Projects
----

[[keyword-remove-roleinstance]]
==== Remove a role instance

[source]
----
remove role <expression>
----

Removes the role instance(s) produced by `<expression>` from their context. The underlying resource is _not_ deleted; use `delete role` for permanent removal.

Example:
[source, arc]
----
remove role origin
remove role filter Tasks with Cancelled
----

==== Delete a role instance

[source]
----
delete role <RoleName> [from <contextExpression>]
----

Permanently deletes the role instance of `<RoleName>` (and the underlying resource). The optional `from` clause identifies the context; when omitted, the current context is used.

Example:
[source, arc]
----
delete role TempData
----

==== Bind (fill) a role

[source]
----
bind <expression> to <RoleName> [in <contextExpression>]
----

Fills an existing, unfilled instance of `<RoleName>` with the role instance(s) produced by `<expression>`. If no unfilled instance exists, one is created first.

Example:
[source, arc]
----
bind me to Participant
bind currentactor to Manager in Projects
----

==== Bind to an explicit binder (`bind_`)

[source]
----
bind_ <expression> to <binderExpression>
----

Fills the binder role instance produced by `<binderExpression>` with the role instance produced by `<expression>`. The binder must be an existing role instance.

Example:
[source, arc]
----
bind_ app >> extern to start
----

[[keyword-remove_filler]]
==== Remove the filler of a role, starting with the filled role

[source]
----
remove filler of <filled-role-expression>
----

Detaches the filler of the role instance(s) produced by `<filled-role-expression>`.

Example:
[source, arc]
----
remove filler of Participant
remove filler of currentactor
----

[[keyword-remove_filled]]
==== Remove the filler of a role, starting with the filling role
[source]
----
remove as filler of <filler-role-expression>
----

Detaches the role instance(s) produced by `<filler-role-expression>` from all role instance(s) they fill.

We can restrict that to a specific filled role by specifying a role type:

[source]
----
remove as filler of <RoleType> <filler-role-expression> 
----

Examples:
[source, arc]
----
remove as filler currentactor
remove as filler of Participant me
----

==== Severing the link between specific role instances
Finally, we can remove the link between a specific filled role and a specific filler role:

[source]
----
remove filler <filler-role-expression> from <filled-role-expression>
----

==== Move a role

[source]
----
move <expression> [to <contextExpression>]
----

Moves the role instance(s) produced by `<expression>` to the context produced by `<contextExpression>`. When `to` is omitted, the role is moved to the current context.

Example:
[source, arc]
----
move origin to TargetContext
----

[[assignments-context]]
=== Context assignments

==== Create a context

[source]
----
create context <ContextType> [named <expression>] [bound to <RoleType>] [in <contextExpression>]
----

Creates a new instance of `<ContextType>`. Options:

* `named <expression>` — provides a local name or indexed name for the new context.
* `bound to <RoleType>` — fills the named role type in the target context with the new context's external role.
* `in <contextExpression>` — places the context role into the specified context; when omitted, the current context is used.

Example:
[source, arc]
----
create context Project
create context Meeting bound to Meetings in sys:MySystem
----

==== Create a context with an explicit filler (`create_`)

[source]
----
create_ context <ContextType> [named <expression>] bound to <roleExpression>
----

Creates a new instance of `<ContextType>` and fills the role instance produced by `<roleExpression>` with its external role. Unlike `create context`, this form takes a role _expression_ rather than a role _type name_.

Example:
[source, arc]
----
create_ context Meeting bound to contextRole
----

[[keyword-remove_contextinstance]]
==== Remove a context

[source]
----
remove context <expression>
----

Removes the context role instance(s) produced by `<expression>` from their parent context, together with the contexts that fill them. The removal is shared with peers.

Requires a perspective on the role with `RemoveContext` or `DeleteContext`.

`<expression>` may produce instances of two kinds of role. The statement handles them differently:

* *Context roles.* This is the usual case: `<expression>` produces instances of a context role, such as `Meetings`. Both the context role instance and the context that fills it are removed.
* *External roles.* `<expression>` produces the external roles of contexts. This is typical for a calculated context role such as `context MyContracts = me >> binder AccountHolder >> context >> extern`. Its instances _are_ the external roles of the contracts; they are not context roles that hold them. In this case, the context of each external role is removed (and with it, that external role). The context roles that the external role fills are not removed: they remain, but lose their filler. This happens in every installation that has such a context role and receives the removal.

[[remove-context-through-external-role]]
===== Removing a context through its external role

Why would you remove a context through its external role? Because the context role that holds the context may not be available to the user who wants to remove it. A context role is stored in the context that contains it. If that context is not shared with the user, the user does not have the context role, even though she does have the context that fills it.

Consider a contract between an account holder and a service. The service keeps track of its contracts in a context role `Accounts`. Only the service's administrator has that role; an account holder does not. To list her contracts, an account holder uses a calculated context role that starts from herself:

[source, perspectivesarc]
----
case MyApp
  context Contracts = me >> binder AccountHolder >> context >> extern

  user Manager = sys:Me
    perspective on Contracts
      only (RemoveContext)
    action RemoveAllContracts
      remove context Contracts
----

When the Manager removes the contracts, they are removed from her installation. The removal is shared with the users who play a role in each contract, such as the administrator. In the administrator's installation the contract is removed as well, and her `Accounts` role instance remains without a filler. Users who only have a perspective on `Accounts` (and play no role in the contract) are not informed.

The same applies when the end user removes a context in a screen. If the user has a perspective with `RemoveContext` on a calculated context role whose instances are external roles, the end user can remove a context from a table or form for that role. The effect is the same as that of `remove context`.

NOTE: You can also remove the current context with `remove context extern`.

[[keyword-remove_contextlocally]]
==== Remove a context locally

[source]
----
remove context locally <expression>
----

Removes the contexts that fill the context role instance(s) produced by `<expression>` from this installation only. The removal is not shared with peers: for them, the context remains. Neither are removals done by the `on exit` actions of the removed contexts and their roles; other changes made by those actions are shared as usual.

Removing a context locally means leaving it. The user role instances that the user fills in the context are removed in the installations of the other participants. Hence a user who may remove a context locally may leave it, and a user who may not, cannot.

The context role instances themselves remain. In this installation they no longer have a filler; for peers they stay filled. To remove them as well, add `remove role <expression>`.

If `<expression>` produces external roles, for example through a calculated context role, the contexts of those external roles are removed locally. See <<remove-context-through-external-role>>.

Requires a perspective on the context role with `RemoveContextLocally`, `RemoveContext` or `DeleteContext`.

Example:
[source, arc]
----
user Member
  perspective on Subscriptions
    only (RemoveContextLocally)
  action UnsubscribeFromAll
    remove context locally Subscriptions
----

==== Delete a context

[source]
----
delete context bound to <ContextRoleName> [from <contextExpression>]
----

Permanently deletes the context that is bound (via its external role) to `<ContextRoleName>`. The optional `from` clause identifies the containing context.

Example:
[source, arc]
----
delete context bound to Projects
----

[[assignments-file]]
=== File creation

[source]
----
create file <fileNameExpression> as "<mimeType>" in <PropertyName> [for <roleExpression>]
  <contentExpression>
----

Creates a file with:

* a name given by `<fileNameExpression>` (a string expression),
* a MIME type given by the literal string `<mimeType>` (e.g. `"text/plain"`, `"text/json"`),
* stored as the value of `<PropertyName>` (which must be a `File` property),
* its content provided by `<contentExpression>` (indented on the next line).

Example:
[source, arc]
----
create file ("export_" + context >> Title + ".json") as "text/json" in MyExport
  callExternal ser:SerialiseFor( [role SomeRole], extern ) returns String
----

=== Running actions
It is possible to programmatically trigger context and role actions using the `runContextAction` and `runRoleAction` keywords, respectively. Not an assignment itself, these keywords allow for the execution of predefined actions within the model.

[[keyword-runContextAction]]
==== `runContextAction`

[source]
----
runContextAction <ActionName> for <UserRoleType> in <contextExpression>
----

Runs the named context action on behalf of the local user in each context produced by `<contextExpression>`. A context is acted on only when the local user has an instance of `<UserRoleType>` in that context. The action is fully executed, including its `once settled` stages, before the next context is processed.

[[keyword-runRoleAction]]
==== `runRoleAction`

[source]
----
runRoleAction <ActionName> for <UserRoleType> on <roleExpression> in <contextExpression>
----

Runs the named role action on behalf of the local user for each role instance produced by `<roleExpression>`. The user must have an instance of `<UserRoleType>` in `<contextExpression>`. Each action is fully executed, including its `once settled` stages, before the next role instance is processed.

[[assignments-effects]]
=== External effects

==== `callEffect`

[source]
----
callEffect <EffectName>(<arg> {, <arg>}*)
----

Invokes a _non-destructive_ external effect function by name. The function may read data but must not modify the model state.

==== `callDestructiveEffect`

[source]
----
callDestructiveEffect <EffectName>(<arg> {, <arg>}*)
----

Invokes a _destructive_ external effect function that may modify data outside the Perspectives model (for example, sending an email, writing to an external database).

Example:
[source, arc]
----
callDestructiveEffect notifications:SendEmail( EmailAddress, Subject, Body )
----
